# ПАТИБАС · локальный пульт

MVP для одного ноутбука и подключённых планшетов/телефонов. Node.js + `ws`, обычные HTML/CSS/JS без сборки и внешних сервисов. Архитектура из [прикреплённого диалога](https://chatgpt.com/share/6aaa3998-861c-83eb-bdf7-aabe0dfd4261): **PRELOAD → READY → PLAY по общей метке времени**. Фиксированного лимита устройств нет: пульт показывает фактическое количество подключений. Практическая ёмкость зависит от Wi-Fi и ноутбука.

## Запуск на этом ноутбуке

Зависимости уже установлены. Откройте `start.cmd` двойным щелчком либо выполните в папке проекта:

```powershell
node server.js
```

Оставьте окно сервера открытым. Пульт: **http://localhost:3000/admin**. Только один пульт одновременно; он доступен с самого ноутбука. Адреса для планшетов печатаются при запуске и отображаются внизу пульта. Выбирайте адрес Wi-Fi адаптера, а не виртуальной сети/VPN. Во время разработки адрес Wi-Fi: `http://192.168.1.231:3000`; после смены сети он может измениться.

На другом компьютере нужен Node.js 22 или новее. Перед первым запуском с интернетом выполните `npm install` (либо `pnpm install --frozen-lockfile`), затем `npm start`. Во время работы интернет не требуется.

## Показ

1. Подключите ноутбук и планшеты к одной локальной сети. Планшеты должны иметь доступ к TCP-порту 3000 ноутбука. Гостевая сеть с изоляцией устройств может мешать. При запросе Windows Firewall разрешите серверу доступ в вашей частной сети.
2. Скопируйте ролики в `media`, затем нажмите **Обновить**. Предпочтителен MP4 с H.264; WebM поддерживается, если его декодирует браузер планшета. Сначала проверьте конкретные файлы на одном устройстве.
3. Нажмите на нужный IP-адрес внизу пульта: откроется окно с QR-кодом. Отсканируйте его камерой планшета либо введите адрес вручную и нажмите **Подключиться к показу**. Свободный номер назначится автоматически; при желании укажите свой уникальный номер места. Кнопка **Полный экран** доступна до показа. QR-код генерируется локально, без интернета; окно закрывается крестиком, Escape или нажатием вне окна.
4. В пульте выберите ролик и нажмите **Загрузить на планшеты**. Каждый планшет полностью скачает файл, создаст локальный Blob и проверит воспроизведение без звука. READY означает завершённую загрузку, доступный декодер и синхронизированные часы.
5. После загрузки аудио нажмите **Разрешить звук** на ноутбуке. Это действие снимает браузерное ограничение автозапуска; проверка выполняется с нулевой громкостью. Громкость показа регулируется в системе/колонках.
6. Дождитесь READY **всех подключённых устройств** и готовности аудио. Для запуска достаточно одного подключённого экрана, без экранов запуск заблокирован. **Запустить синхронно** назначает старт через 2 секунды. Видео планшетов всегда `muted`; аудио идёт из пульта ноутбука.
7. Доступны пауза, стоп, ±10 секунд и ползунок позиции. Перемотка запускает показ с выбранной позиции после нового общего отсчёта. Стоп возвращает к началу, сохраняя загруженные файлы.

При подключении нового экрана во время показа, потере планшета/пульта либо сообщении о неготовности сервер приостанавливает показ. Новый экран автоматически загружает текущий ролик. Открытое WebSocket-соединение проверяется каждые 5 секунд; потеря сети обнаруживается обычно за 5–10 секунд. Переподключение автоматическое. Отключённые экраны удаляются из счётчика; продолжить можно после готовности оставшихся подключённых устройств. Если место занято, перезагрузите страницу и оставьте номер пустым для автоматического назначения.

## Видео и звук

У каждого подключённого экрана в пульте есть кнопка **Исключить**. Она отключает выбранное соединение и сразу убирает его из счётчика и проверки READY. На устройстве останавливаются видео и загрузка; автоматического переподключения после исключения нет. Для возврата нужно обновить страницу и снова подключиться. Остальные экраны продолжают показ; при исключении последнего показ приостанавливается. Это отключение текущего соединения, а не постоянная блокировка устройства.

```text
media/
  Караоке.mp4
  Караоке.mp3
  Поздравление.mp4
```

Если рядом с видео есть файл с тем же именем и расширением `.mp3`, `.m4a` или `.wav`, ноутбук воспроизводит его. Если отдельного файла нет, пульт использует аудиодорожку самого видео через `<audio>`. У видео без аудиодорожки звука не будет. На планшетах звук отключён в обоих случаях.

Начало аудио должно соответствовать началу видео. Разница длительности больше 1 секунды блокирует запуск. Bluetooth и обработка звука колонками могут добавлять задержку, которую этот MVP не измеряет; проверяйте фактическую синхронизацию с выбранной акустикой.

`demo-flower.mp4` — короткий тестовый клип из [CC0-примеров MDN](https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4). Он добавлен для проверки видеотракта; для проверки звучания используйте свой ролик с известной аудиодорожкой или отдельный аудиофайл.

## Проверка

Подключите любое нужное количество устройств. Настраивать число клиентов перед запуском больше не требуется; прежняя переменная `EXPECTED_CLIENTS` не используется.

```powershell
node server.js
```

Откройте пульт и клиент в отдельных окнах, которые браузер не скрывает/не замораживает. Порт меняется через `$env:PORT = '3001'`.

Автоматические проверки:

```powershell
node --test
```

Проверяются 30 WebSocket-клиентов, подключения сверх 30, автоматические и произвольные номера, динамический барьер READY, одинаковая временная метка, пауза/перемотка, повторное и позднее подключение, устаревшие сообщения, несовпадение длительностей, доступ к пульту, занятые места, запрет команд от планшетов, HTTP Range и локальная выдача QR-кодов.

В браузере проверены реальный MP4, полная предзагрузка, READY, снятие ограничения звука, отсчёт, воспроизведение видео с `muted=true`, пауза и завершение. Это не испытание 30 физических планшетов или акустики автобуса.

## Устройство проекта

- `server.js`: HTTP-медиатека, выдача файлов с Range, WebSocket, состояние показа и контроль готовности.
- `public/player.js`: общий проигрыватель планшета/аудио пульта, загрузка Blob, синхронизация часов, планирование и коррекция позиции.
- `public/admin.*`: пульт и статусы мест.
- `public/client.*`: выбор места и полноэкранное видео.
- `test/server.test.js`: интеграционные тесты сервера.

Протокол: `HELLO`, `SYNC`, `PRELOAD`, `STATUS`, `PLAY`, `PAUSE`, `STOP`, `SEEK`, `STATE`, `ERROR`. У каждой загрузки уникальный `generation`: READY старого ролика игнорируется. `revision` отменяет старые отложенные команды. Серверное время и локальные часы используют монотонный `performance`; смещение оценивается по обменам с минимальным RTT. До READY нужны минимум три измерения.

Позиция рассчитывается как `position + (serverTime - startAt) / 1000`. Раз в секунду клиент сверяется с временной шкалой. При отклонении 60–300 мс скорость меняется на ±2%, при большем — выполняется перемотка. Это браузерная синхронизация, а не покадровый genlock: точность зависит от декодера, устройства и планировщика. На реальных планшетах её нужно измерить перед рейсом.

## Границы MVP

- Загружается **один выбранный ролик** целиком в память каждого браузера. После закрытия/перезагрузки страницы нужна новая загрузка. Постоянного офлайн-кэша всей медиатеки пока нет. Для больших роликов учитывайте память планшета и пиковые копии при создании Blob.
- Все подключённые устройства загружают ролик по Wi-Fi одновременно. Подготовьте видео заранее и дождитесь READY; во время показа видео по сети не стримится. Таймаут загрузки — 10 минут, подготовки декодера — 30 секунд.
- Держите страницы на переднем плане и исключите сон устройств. При скрытии страницы она снимает READY. Wake Lock запрашивается, если браузер позволяет его; на обычном HTTP по LAN он может быть недоступен, поэтому настройте длительность работы экрана вручную.
- Пульт доступен только с loopback-адреса ноутбука, команды от клиентов запрещены, Origin WebSocket проверяется. Система предназначена для доверенной локальной сети: HTTPS, аккаунтов и паролей устройств в MVP нет.
- Нет live-stream, редактора субтитров, плейлиста и текстового режима. Загрузка контента выполняется копированием в `media`.
